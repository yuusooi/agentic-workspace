## 1. 成员管理面板

### 1.1 入口

看板页工具栏 → 点击「成员管理」按钮 → 右侧弹出 Drawer（宽度 400px）

### 1.2 成员列表

```
┌──────────────────────────────────┐
│  成员管理                    [×]  │
├──────────────────────────────────┤
│  ┌─────────────────────────────┐ │
│  │ [张] 张三                   │ │
│  │ zhangsan@example.com        │ │
│  │ 角色: [PROJECT_OWNER ▾]  · │ │
│  └─────────────────────────────┘ │
│  ┌─────────────────────────────┐ │
│  │ [李] 李四                   │ │
│  │ lisi@example.com            │ │
│  │ 角色: [PROJECT_MEMBER ▾] × │ │
│  └─────────────────────────────┘ │
│  ...                             │
├──────────────────────────────────┤
│  邀请新成员（仅项目负责人可见）      │
│  [输入账号（username）______] [邀请]│
└──────────────────────────────────┘
```

### 1.3 交互规则

| 操作         | 触发                | 权限             | 行为                                                              |
| ------------ | ------------------- | ---------------- | ----------------------------------------------------------------- |
| 查看成员列表 | 打开 Drawer         | 所有项目成员     | 展示头像、名称、邮箱、角色                                        |
| 修改角色     | 点击角色下拉        | 仅 PROJECT_OWNER | 下拉切换 OWNER/MEMBER，确认后立即生效                             |
| 移除成员     | 点击 × 按钮         | 仅 PROJECT_OWNER | Popconfirm 确认后移除，不能移除自己                               |
| 邀请成员     | 输入账号 → 点击邀请 | 仅 PROJECT_OWNER | 成功后列表新增一行，失败显示错误提示                              |
| 查看成员任务 | 点击成员头像/名称   | 所有项目成员     | 关闭 Drawer，看板筛选只显示该成员的任务（顶部显示筛选条，可清除） |

### 1.4 成员任务筛选

点击成员后，看板顶部出现筛选条：

```
[×] 筛选：张三负责的任务                    [清除筛选]
```

筛选条存在时，看板所有列只显示该 `assignee_id` 对应的任务。筛选条右侧有「清除筛选」按钮。

## 2. 同列内拖拽排序

### 2.1 交互行为

| 操作             | 行为                                                 |
| ---------------- | ---------------------------------------------------- |
| 拖起任务卡片     | 卡片半透明 + 阴影提升，原位置显示占位符（虚线边框）  |
| 拖入同列其他位置 | 占位符跟随鼠标位置移动，实时指示插入点               |
| 放下（同列）     | 卡片插入到占位符位置，更新 position 值，调用排序 API |
| 放下（跨列）     | 与现有行为一致：更新 column_id + status              |

### 2.2 视觉反馈

- 拖拽中卡片：`opacity: 0.5`，`box-shadow: 0 8px 24px rgba(0,0,0,0.15)`
- 目标位置占位符：`border: 2px dashed #0075de`，`background: rgba(0,117,222,0.04)`，高度与被拖卡片一致
- 同列内拖拽时，列头状态圆点不变化（因为不改变状态）
- 跨列拖拽时，目标列头闪现蓝色高亮（现有行为）

### 2.3 数据同步

拖拽完成后，前端计算受影响任务的 position 值（目标位置前后的任务 position 需要重新分配），批量调用 `PUT /api/columns/{id}/tasks/reorder`。失败时回滚并提示。

## 6. 登录失败锁定 UI

### 6.1 状态流转

```
正常状态 → 输入错误密码 → 显示错误提示
  ↓ (失败 1-4 次)
显示剩余尝试次数
  ↓ (失败第 5 次)
锁定状态：禁用表单 + 显示倒计时
  ↓ (15 分钟后)
自动解锁：恢复正常状态
```

### 6.2 UI 状态

| 状态                | 表现                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| 正常                | 标准登录表单                                                                                            |
| 密码错误（1-3 次）  | 红色提示 "邮箱或密码错误"，表单可继续提交                                                               |
| 即将锁定（第 4 次） | 橙色警告 "还有 1 次尝试机会，失败后账户将被锁定 15 分钟"                                                |
| 已锁定（第 5 次）   | 整个表单禁用（输入框灰色 + 按钮灰色不可点击），显示：`🔒 账户已锁定，请 14:32 后重试`（倒计时每秒更新） |
| 锁定过期            | 自动恢复正常状态，重置失败计数                                                                          |

### 6.3 倒计时格式

- 剩余 > 1 分钟：`请 14:32 后重试`（显示具体时间）
- 剩余 ≤ 1 分钟：`请 58 秒后重试`（显示秒数）
- 倒计时结束时：自动移除锁定状态，表单恢复可用

## 8. @提及输入自动补全

### 8.1 触发机制

在进度输入框中输入 `@` 字符时，触发成员候选列表。

| 触发条件           | 行为                                               |
| ------------------ | -------------------------------------------------- |
| 输入 `@`           | 弹出候选列表，显示项目全部成员（最多 10 人）       |
| `@` 后继续输入文字 | 过滤匹配的成员（如 `@张` → 只显示"张三"）          |
| 候选列表为空       | 不显示下拉，`@` 作为普通文本                       |
| 选中成员           | 插入 `@username ` 到文本中（末尾带空格），关闭下拉 |
| 按 Esc             | 关闭候选列表，保留已输入的 `@xxx` 文本             |

### 8.2 候选列表 UI

```
┌──────────────────────────────┐
│  [张] 张三                    │  ← 匹配高亮
│  [张] 张四 (zhang4@mail.com)  │
│  [王] 王五                    │
└──────────────────────────────┘
```

- 位置：输入框下方，紧贴光标位置
- 每项显示：头像（20px）+ 名称 + 邮箱（灰色）
- 匹配文字高亮（蓝色加粗）
- 键盘上下选择 + Enter 确认

### 8.3 展示进度中的 @提及

进度渲染时，`@username` 文本替换为蓝色高亮（展示为 `@显示名称`）：

```
存储文本：@zhangsan 请看一下这个bug，@lisi 也帮忙review
渲染效果：@张三 请看一下这个bug，@李四 也帮忙review
          ^^^^                   ^^^^
          蓝色 #0075de            蓝色 #0075de
          font-weight: 500       font-weight: 500
```

点击高亮的 @显示名称 → 打开该用户的资料浮层（头像、名称、邮箱、当前任务数）。

### 8.4 前端实现方案

使用 Ant Design 的 `Mentions` 组件（antd 内置），配置：

```typescript
<Mentions
  placeholder="添加进度... (@提及成员)"
  onChange={handleChange}
  onSelect={handleSelect}
  options={members.map(m => ({
    value: m.username,
    label: (
      <div style={{ display: 'flex', alignItems: 'center', gap: 8 }}>
        <Avatar size={20}>{m.name[0]}</Avatar>
        <span>{m.name}</span>
        <span style={{ color: '#a39e98' }}>{m.email}</span>
      </div>
    )
  }))}
/>
```

**说明：** `value` 使用 `username`（唯一标识），确保 @提及的匹配键全局唯一。`label` 展示 `name`（显示名称）+ 邮箱供用户识别。选中后插入的文本为 `@username`（如 `@zhangsan`），后端按 `username` 匹配 `User` 表。

前端渲染进度时，将 `@username` 替换为 `@name`（显示名称）并高亮：

```typescript
function renderMentions(content: string, memberMap: Map<string, string>) {
  return content.replace(/@(\S+)/g, (match, username) => {
    const displayName = memberMap.get(username);
    if (displayName) {
      return `<span class="mention" style="color:#0075de;font-weight:500">@${displayName}</span>`;
    }
    return match;
  });
}
```

提交进度时，前端从 content 中提取所有 `@username`，与项目成员表匹配，生成 mentions 列表（后端也会做同样的解析和校验）。

## 9. 前端鉴权体系

### 9.1 权限数据流

```
登录/注册 API → 返回 user 对象（含 role, can_create_project）
  → Zustand authStore 存储全局角色信息
    → 项目列表页：根据 can_create_project 决定是否显示「创建项目」按钮
    → 进入项目看板 → GET /api/projects/{id}/board 返回 my_role
      → Zustand projectStore 存储当前项目角色
        → 根据 my_role 控制看板页面内按钮/菜单的显隐
```

**Zustand Store 设计：**

```typescript
// authStore
interface AuthState {
  user: {
    id: string;
    username: string;
    name: string;
    email: string;
    role: "ADMIN" | "USER";
    can_create_project: boolean;
    avatar: string | null;
  } | null;
  isAuthenticated: boolean;
}

// projectStore（进入项目时设置）
interface ProjectState {
  currentProject: {
    id: string;
    name: string;
    my_role: "PROJECT_OWNER" | "PROJECT_MEMBER";
  } | null;
}
```

### 9.2 权限判断工具函数

```typescript
function isAdmin(user: AuthState["user"]): boolean {
  return user?.role === "ADMIN";
}

function canCreateProject(user: AuthState["user"]): boolean {
  return user?.role === "ADMIN" || user?.can_create_project === true;
}

function isProjectOwner(project: ProjectState["currentProject"]): boolean {
  return project?.my_role === "PROJECT_OWNER";
}
```

系统管理员（ADMIN）在所有项目中等同于 PROJECT_OWNER，前端通过 `isAdmin(user) || isProjectOwner(project)` 判断。

### 9.3 全局级 UI 元素权限

以下 UI 元素根据全局角色（`authStore.user`）控制显隐：

| UI 元素 | 可见条件 | 说明 |
| ------- | -------- | ---- |
| 顶部导航栏「创建项目」按钮 | `canCreateProject(user)` | 不满足条件时隐藏按钮 |
| 项目列表页「创建项目」按钮 | `canCreateProject(user)` | 同上 |
| 侧边栏/导航「系统管理」入口 | `isAdmin(user)` | 仅系统管理员可见，点击进入用户管理页面 |

### 9.4 项目级按钮权限表

以下 UI 元素根据当前项目角色（`projectStore.currentProject.my_role`）控制显隐。系统管理员始终等同于 OWNER。

| 按钮 / 操作 | 位置 | OWNER | MEMBER | 说明 |
| ----------- | ---- | ----- | ------ | ---- |
| 成员管理按钮 | 看板工具栏 | ✅ | ✅ | 所有成员可打开 Drawer，但邀请/移除/改角色仅 OWNER 可操作（Drawer 内控制） |
| 邀请新成员输入框 | 成员管理 Drawer | ✅ | ❌ | 仅 OWNER 可见 |
| 角色下拉切换 | 成员管理 Drawer 成员行 | ✅ | ❌ | 仅 OWNER 可操作 |
| 移除成员 × 按钮 | 成员管理 Drawer 成员行 | ✅ | ❌ | 仅 OWNER 可见 |
| 新增看板列按钮 | 看板工具栏 | ✅ | ❌ | |

### 9.5 权限不足的页面处理

| 场景 | 处理方式 |
| ---- | -------- |
| 未登录访问需认证页面 | 重定向到登录页，登录后跳回原页面 |
| 非项目成员访问项目看板 | 显示 403 页面，提示「您不是该项目成员」，提供返回项目列表链接 |
| 无项目创建权限点击创建项目 | 按钮直接隐藏，不会出现此场景 |
| MEMBER 尝试 OWNER 操作（如通过 API 直接调用） | 后端返回 403，前端展示全局错误提示 |

### 9.6 系统管理员前端入口

系统管理员不需要独立的管理页面。系统管理员通过以下方式行使全局管理权限：

1. **用户管理入口：** 当 `authStore.user.role === "ADMIN"` 时，在顶部导航栏/侧边栏显示「用户管理」入口，点击跳转用户列表页面。该页面使用 `GET /api/admin/users` 获取用户列表，支持修改角色（`PUT /api/admin/users/{id}/role`）和启用/禁用用户（`PUT /api/admin/users/{id}/status`），以及设置 `can_create_project` 权限
2. **项目权限：** 系统管理员进入任何项目时，`my_role` 始终为 `PROJECT_OWNER`，所有 OWNER 操作按钮自动可见
3. **项目列表：** 系统管理员通过 `GET /api/admin/projects` 可查看所有项目（不仅仅是自己参与的）
